What this is

Pi extensions that add a second "advisor" model to review, guide, or audit the primary agent's work. All share the same goal — prevent the executor from going off the rails — but diverge sharply on when and how the advisor speaks.

Key finding

No two implementations share the same activation model. Choosing one is choosing a philosophy: trust the executor to ask for help, shadow every turn silently, or run a full parallel reviewer.

Quick recommendation
  • Best balance: pasky/pi-omplike-advisor — persistent review, graded severity, self-compacting context, published on pi.dev
  • Direct interrogation: kkkiio/pi-advisor — overlay UI lets you chat with advisor independently
  • Lightest entry: RimuruW/pi-advisor — on-demand tool, zero overhead when not used

Pattern 1: On-Demand Tool

Executor gets an advisor() tool. It decides when to call it — before big decisions, when stuck, or at completion. Advisor model sees curated transcript subset, returns strategic guidance.

Weakness

A dumb executor never asks. You get no second opinion unless the executor knows to request one.

Pattern 2: Persistent Auto-Review

Separate long-lived advisor agent runs in parallel. After each executor turn, advisor reviews the delta and emits graded notes: nit / concern / blocker. Advisor is read-only — cannot edit files or run commands.

Pattern 3: Full Peer Agent

Advisor is a complete second agent session with its own context window. Can be auto-triggered (loops, failures, completion) or manually consulted. User can directly chat with advisor for independent review.

Decision criteria
If you want silent continuous QA

Choose pasky/pi-omplike-advisor. Best maturity, published on pi.dev, self-compacting context, graded severity with re-confirmation logic.

If you want to interrogate the advisor directly

Choose kkkiio/pi-advisor. Overlay UI is unique. You can ask the advisor questions independently while executor works.

If you want minimal overhead

Choose RimuruW/pi-advisor. On-demand tool, zero cost when not called. Good first try before committing to persistent review.

If you want maximum configurability

Choose philipbrembeck/pi-advisor. Context slider, per-gate controls, manual parallel consultations, response collapsing.

Recommendation
Primary recommendation: pasky/pi-omplike-advisor

Best balance of continuous review and maturity. Installed via pi install npm:pi-omplike-advisor, published on pi.dev, 7 stars.

  • Persistent turn-by-turn review
  • Graded severity: nits delivered immediately, concerns/blockers held and re-confirmed
  • Self-compacting context — doesn't fail when session gets long
  • Read-only — advisor can't mutate files
Alternative: kkkiio/pi-advisor

If you want the ability to directly chat with the advisor while the executor works. Overlay UI is unique across all implementations.

Lightweight entry: RimuruW/pi-advisor

If you want to try the concept with zero overhead. On-demand tool — advisor only runs when executor calls it.

What to avoid
CautionPath-load-only extensions (Hopsken/pi-advisor, luongnv89/advisor-pi) — harder to update, not discoverable on pi.dev
NoteExtensions with 0 stars and no npm publish — unmaintained risk
Why not the heaviest option?

Full peer agents (philipbrembeck, kkkiio) are powerful but expensive — two full agents running. Start with persistent review (pasky) and only graduate to peer agents if you find you need direct advisor interrogation.

Glossary
Terms used
  • Executor: The primary agent doing the work
  • Advisor: The secondary model providing review/guidance
  • Turn: One complete agent response cycle
  • Delta: The new content since the last review
  • Nit: Low-severity suggestion (style, minor improvement)
  • Concern: Medium-severity issue (wrong assumption, potential bug)
  • Blocker: High-severity issue (data loss risk, security, wrong path)
Pattern 2 severity delivery semantics (pasky)
  • Nit: Delivered immediately, steered into conversation
  • Concern/Blocker: Held on first emission (review is async, usually stale by delivery time). Re-confirmed by next review cycle. Only delivered if still valid.
Self-compaction (why it matters)

Advisor agents accumulate context over time. Without compaction, they fail when their context window fills. Self-compacting advisors clear their history and replay the current turn into a fresh context — so long sessions keep getting reviewed.
